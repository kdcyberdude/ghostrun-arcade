Native displayed HUD numbers
============================

CPU score, coin and timer digits are separate from the PPU nametable containing the visible HUD. The NMI selects VRAM_Buffer2 when VRAM_Buffer_AddrCtrl ($0773) is 6. That preserves pending VRAM_Buffer1 packets; the ordinary engine control0 selection consumes them. Other fixed screen/message controls select their own source packets and clear buffer1. The number display must retain its previous value until those packets are consumed. Screen initialization clears the time field; the status header writes score/coins, and RunGameTimer prints time on an actual digit tick. The initial 401/301/201 timer sentinel is not a displayed number.

`NativeHud` owns the displayed digits and pending number packets. Simulation steps queue score/coin changes and actual timer prints, then consume the queue according to the existing native palette/VRAM buffer scheduler during engine updates. Source screen initialization owns the separate header/blank-time writes. The renderer reads this state and never advances it. Pending initial buffer1 writes are decoded directly from $0300.. while control6 preserves that buffer.

Arbitrary retained entries also require the initial PPU nametable: CPU RAM alone cannot recover an already displayed older number. `native-mood-hud.ts` compiles the native observer and reads only the requested entry nametable positions. It replays the authenticated complete pad stream from POWER-ON, checks its ROM/pad hashes and the hash of every captured CPU RAM byte against the existing capture, then emits one initial HUD snapshot per entry. The snapshot provenance is copied into the entrance receipt. Entries without this state explicitly report a CPU-digit fallback; they do not claim observed initial HUD coverage. No later PPU state is injected into a remake replay.

The portable regression fixture contains one observed entrance, 999 inputs and 1,000 expected native PPU number displays. All displays match without another RAM or PPU correction. A separate actual RAM case proves that the displayed digits can differ from CPU digits while buffer1 waits behind buffer2, and checks the native release display. Independent decoding of all 2,979 bounded pictures across three authenticated recordings found no unknown number glyphs and exactly follows this queue rule.

Fresh independent browser prefixes of 1,000, 969 and 1,010 pictures all have exactly zero differing pixels across the whole picture, HUD and playfield, with all 142,992,000 playfield pixels compared. Each full input epoch has two additional next-level tail frames outside its strict state prefix; this is bounded evidence, not a whole-epoch pass. Those same prefixes previously retained 342, 181 and 137 differing HUD pixels respectively.

The fair gate exposed a pre-existing scheduler error on castle loopback. A failed native loop subtracts four pages from camera/Mario and replaces the dynamic area object, but still performs that row's scroll/VRAM work. The outer picture scheduler mistook the replaced object for a new area and skipped the row, then discarded its real scroll delta. The fix records the native four-page rewind and removes it from the scroll delta while retaining that GameEngine update. Captured parser task/scroll bytes now match across the actual loopback rows. The portable loop fixture replays three supported prefixes without corrections; later 8-4 loop rows following its earlier state divergence are explicitly listed as excluded evidence.

Validation: all 1,787 tests and TypeScript pass. Regenerated v2 excerpts and all 256 first-field values are unchanged. The fair 32-level sampled picture gate against e3481e7 reduces HUD differing pixels from 18,434 to 14,078 (whole picture 223,343 to 218,987). Playfield/aligned counts remain 204,909/102,787, with no individual frame increase in any metric. All three loop-affected levels were re-run after the scheduler repair; independent picture prefixes use the same unchanged normal-engine path. These sampled totals retain other known errors and are not a completion claim.
