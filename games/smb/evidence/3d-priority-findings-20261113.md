# Native sprite priority in 3D

The ordinary world depth buffer hid foreground NES sprites: at original 1-4 frame 240, six firebar pieces had native visible pixels but zero 3D pixels. A simple foreground/background split is insufficient: a higher-priority sprite with OAM attribute bit 5 set must still mask a lower-priority foreground sprite when the background wins.

`SpritePass` retains a fixed world color/depth image, then renders authored actors with source OAM ordering. Behind-background fragments substitute that fixed world color, keeping their sprite priority mask. Foreground sprites cross terrain without changing their position, size or animation. Model depth remains monotonic in linear view depth around the actor root. A Float32 depth attachment gives each four-byte OAM address its own exponent interval, retaining the depth mantissa even at OAM 252. GTAO runs on the world before actors; actor shadows remain in the world pass. Bloom and the output/color passes still follow actor composition.

The pass restores materials, child order, visibility, background, shadow settings and render target. It owns its copy triangle: Three's `FullScreenQuad.dispose()` disposes a module-global shared geometry, which invalidated subsequent copies in the audit. The GPU regression now runs native row masking after a complete MRT audit and checks that the original world color survives. Actual attachment inspection confirms framebuffer completeness, 32 depth bits and FLOAT components on the RTX 5090 and SwiftShader; high-quality actor/composer attachments are 4x MSAA renderbuffers with internal format DEPTH_COMPONENT32F (36012), and low-quality/copy attachments are 32-bit FLOAT depth textures. Lowest OAM 0/4 ordering is checked explicitly.

The fully retracted Piranha also exposed authored mesh/perspective and pipe-opening differences. The posed mesh is fitted to the native 24px frame using its actual vertices and the camera projection. Native `pir.down` supplies the pipe occlusion row, so a plant behind the native opaque pipe cannot peek through the authored hollow opening. No level, recording or input-specific offsets are used.

- Expanded standard 2,600-frame GPU state/audio equivalence passes: `/tmp/smb-3d-native-priority-equivalence.json`. The tracked receipt is unchanged.
- GPU regressions pass foreground-over-terrain, both cross-bit OAM orders, MRT masking, native pipe-row masking, model self-depth and exception restoration.
- Actual authored Mario face/hat/feet, Koopa/Beetle shells, Piranha and Hammer Bro parts are compared at OAM 0,4,252 (180 cases) in six themes at 256x240 and 1024x960. All native-resolution cases match ordinary model depth. At 960p the Hammer Bro body/hat seam transfers one pixel between those two meshes in each theme; other model cases match. This is an audit result, not a claim of all-frame freedom from flicker/z-fighting: `/tmp/smb-3d-authored-model-depth.log`.
- Five selected native samples preserve simulation/scene/HUD hashes and have no page errors. The fully retracted 1-2:1320 plant has zero visible pixels in both pictures, and 1-4:240 firebar pieces are restored. The remaining 1-4:360 diagnostic is a two-pixel overlap between adjacent authored fire spheres (47/49 sphere pixels visible): `/tmp/smb-3d-native-priority-final-samples.json`.

Coverage limits remain explicit. Whole actor models use their primary OAM block, rather than separate per-CHR body-part priorities. Bowser rear, long-firebar duplicate-slot allocation and multi-slot vine segments need their exact source ownership consumed. The available native duplicate bank/rearSlot APIs are being integrated by the mechanic owners. Cannon frame-timer priority will consume the shared native bullet picture helper when it is canonical. These checks are selected GPU samples, not an all 32 every-frame visual pass. The independent immutable 49a9ae0 baseline already passes every-frame expanded state/audio equivalence and placement for all 146,036 original input frames, but predates this render change.
