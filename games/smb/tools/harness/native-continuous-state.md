# Continuous World1-1 dashboard state readout

`combined-monitor-audit.ts` is a versioned successor of the existing dashboard producer. It retains the inventory and visual policy. Human-corrected v2 counts every observed row independently, including after a mismatch or unchecked prefix; first divergence is diagnostic only. Original32 `strictCompare` initialization and legacy first summaries are retained, with a frame observer supplying actual row classifications. For POWER-ON mood inputs, it now calls `captureLiveWorld1State` after each actual browser input step and compares that snapshot against that input's native RAM row. The existing picture comparison retains its one-frame PPU lag. The browser receives no native RAM, positions, future samples or initialization snapshot. There is no mid-recording reset or `initializeEntrance` call for moods.

The source-owned startup snapshot, when present, exposes `nativeStartup.{mode,task,engine,screen,disable,initializing}`. Its RAM controls, FrameCounter, interval and RNG can be checked during boot/title. Actual PPU mask/control registers are not substituted with RAM mirrors. At recorded start, the native2048-byte FF initial RAM is authenticated and its supported control fields compared with the model's source-owned cold snapshot before any input. `initialStateVerified` becomes true only when this check returns match; missing startup ownership stays unchecked. When the source CPU owner exposes `nativeColdRam`, the initial-only readout compares all2048 bytes instead. Ordinary title RAM is never synthesized. Initial verification is retained as provenance; each later row is classified by its own supported state observations.

During World1-1 gameplay, required scalar fields are death, timer, score, coins, camera and Mario X/Y. Scene origins follow current native AreaData and InitializeArea page events through the static ROM bindings; no coordinates are fitted. Existing strict entity adapters compare all live enemy/misc slots, including birth rows, missing/extra actors, kinds and positions. Existing available state/alias/vine/firebar subfields remain checked. Unsupported native or model objects create explicit gaps. World1-1 source-owned level/death loads and game-over screens additionally compare GameMode/task/engine/screen/disable, screen timer and remaining columns, parser column, scroll lock, readiness, FrameCounter, interval and RNG. The explicit level/death object identity establishes source GameMode1; arbitrary screen objects do not manufacture that ownership. Scalars, coordinates and live entities continue to be checked while loading. Missing source owners/fields, ambiguous scene bindings and other worlds remain unchecked; unsupported World1-1 control modes retain explicit gaps. Earlier mismatched or unchecked rows retain their actual classifications; they do not contaminate later independently observed matching rows in v2.

The small frozen fixture contains actual POWER-ON rows0..15, the complete initial World1-1 load prefix, initial gameplay and first-Goomba birth rows, with capture provenance and decoded-byte SHA256. The original native-derived scalar oracle tests comparator rejection, not game equivalence. The load proof independently runs the ordinary source constructor and its first eight screen steps, with no native bytes passed into that helper, and compares its controls against genuine native rows61..68. It does not claim that a continuously booted current model matches the complete178-row fixture. The read-only simulation test confirms capture does not advance, reset or inject state.
