# Continuous World1-1 dashboard state readout

`combined-monitor-audit.ts` is a versioned successor of the existing dashboard producer. It accepts the same CLI, inventory, visual policy and sticky first-failure reducer. The original32 `strictCompare` initialization/measurement path remains unchanged. For POWER-ON mood inputs, it now calls `captureLiveWorld1State` after each actual browser input step and compares that snapshot against that input's native RAM row. The existing picture comparison retains its one-frame PPU lag. The browser receives no native RAM, positions, future samples or initialization snapshot. There is no mid-recording reset or `initializeEntrance` call for moods.

The source-owned startup snapshot, when present, exposes `nativeStartup.{mode,task,engine,screen,disable,initializing}`. Its RAM controls, FrameCounter, interval and RNG can be checked during boot/title. Actual PPU mask/control registers are not substituted with RAM mirrors. At recorded start, the native2048-byte FF initial RAM is authenticated and its supported control fields compared with the model's source-owned cold snapshot before any input. `initialStateVerified` becomes true only when this check returns match; missing startup ownership stays unchecked. This checks the supported cold control contract, not an invented complete2048-byte model RAM image.

During World1-1 gameplay, required scalar fields are death, timer, score, coins, camera and Mario X/Y. Scene origins follow current native AreaData and InitializeArea page events through the static ROM bindings; no coordinates are fitted. Existing strict entity adapters compare all live enemy/misc slots, including birth rows, missing/extra actors, kinds and positions. Existing available state/alias/vine/firebar subfields remain checked. Unsupported native or model objects create explicit gaps. Other worlds and incomplete World1-1 load/control modes remain unchecked. Later matching observations cannot clear an earlier unchecked prefix or sticky failure in the unchanged consumer.

The small frozen fixture contains actual POWER-ON rows0..15, initial World1-1 gameplay and first-Goomba birth rows, with capture provenance and decoded-byte SHA256. Its native-derived oracle tests comparator rejection, not game equivalence. The read-only simulation test confirms capture does not advance, reset or inject state. The current002743d startup owner is absent: a focused real-browser pilot still correctly reports ten unchecked state rows followed by the existing visual failure at frame9.
