# Native World1-1 POWER-ON and title controls

The continuous dashboard starts at genuine CPU RAMFF / PPUdot0. It must not begin at an observed gameplay entrance. Native cold Start waits for two PPU vblanks, then executes memory/PPU setup. The first title InitializeGame contains two InitializeMemory calls and spans sampled PPU boundaries. `native-title-controls.ts` owns only the ordinary source NMI/title tasks after that CPU initializer returns. It is not a fixed startup delay or a replacement for the separate cold CPU microsequencer.

`nativeTitleControlsFromRam` is the transfer API from CPU-owned RAM. In production that RAM must be generated by the cold microsequencer itself, never copied from a future recording row. The focused helper regression has an explicit one-time native post-initializer condition and makes no live continuous-start claim. The helper models ordinary NMI FrameCounter/LFSR/interval/demo/select timers, ScreenRoutines tasks, palette commands, PrimaryGameSetup, engine0/7 entrance setup, source ReadJoypads masks, Select and Start dispatch. Timer setting comes from native RAM0715, previously decoded from the ROM header. Unsupported demo playback returns an explicit effect; it is not silently counted as verified gameplay.

The source ReadJoypads reverses the incoming A..Right bit order. Repeated Start/Select bits already in JoypadBitMask are suppressed until release. GameMenu accepts exactly Start or A+Start, rather than any button chord containing Start. It ignores B+Start. Selection uses the source SelectTimer, and accepted Start preserves the title's retained screen14/engine state while switching mode1/task0. Runtime handoff must create the existing source level-load object using those retained bytes and pass its native clocks; it must not restart a fitted intro duration.
