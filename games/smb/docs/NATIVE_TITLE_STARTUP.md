# Native World1-1 POWER-ON and title controls

The continuous dashboard starts at genuine CPU RAMFF / PPUdot0. It must not begin at an observed gameplay entrance. Native cold Start waits for two PPU vblanks, then executes memory/PPU setup. The first title InitializeGame contains two InitializeMemory calls and spans sampled PPU boundaries. `native-title-controls.ts` owns only the ordinary source NMI/title tasks after that CPU initializer returns. It is not a fixed startup delay or a replacement for the separate cold CPU microsequencer.

`nativeTitleControlsFromRam` is the transfer API from CPU-owned RAM. In production that RAM must be generated by the cold microsequencer itself, never copied from a future recording row. The focused helper regression has an explicit one-time native post-initializer condition and makes no live continuous-start claim. The helper models ordinary NMI FrameCounter/LFSR/interval/demo/select timers, ScreenRoutines tasks, palette commands, PrimaryGameSetup, engine0/7 entrance setup, source ReadJoypads masks, Select and Start dispatch. Timer setting comes from native RAM0715, previously decoded from the ROM header. Unsupported demo playback returns an explicit effect; it is not silently counted as verified gameplay.

The source ReadJoypads reverses the incoming A..Right bit order. Repeated Start/Select bits already in JoypadBitMask are suppressed until release. GameMenu accepts exactly Start or A+Start, rather than any button chord containing Start. It ignores B+Start. Selection uses the source SelectTimer, and accepted Start preserves the title's retained screen14/engine state while switching mode1/task0. Runtime handoff must create the existing source level-load object using those retained bytes and pass its native clocks; it must not restart a fitted intro duration.

## Live state wiring

`Simulation.reset(false)` on World1-1 now constructs `NativeColdStartup` with its own coldFF RAM. Every source PPU step runs that instruction/cycle/PPU microsequencer until it completes the first InitializeGame, then transfers its generated control RAM to the ordinary title controller. `nativeColdRam` exposes CPU-owned RAM only while that owner is active, allowing the audit to authenticate the full initial2048-byte FF state. No capture RAM is passed to the live model. The raw-pad transport starts with an empty queue, matching one source controller byte per PPU frame.

An accepted Start creates `levelLoad` with the actual retained screen14/engine/disable/timer/columns, publishes the final Start picture event, then clears `nativeStartup`. Existing level-load control owns subsequent frames. InitializeArea's partial page7 pass clears parser column/scroll/task/lock before lower player bytes; the handoff no longer retains a completed title-parser column. GameEngine's first setup/PlayerRdy passes also run ColorRotation when FrameCounter&7=0. Engine7 remains in the intro/control-owned phase until actual PlayerRdy, while its source screen state still exposes the first world picture.

The source color-offset byte remains modulo6 in the title controller. The renderer's existing `colorRotations` variable counts completed color writes; keeping that count unbounded preserves the loaded-palette distinction across offset wrap and CPU-only memory clears. Cold invalid NumberOfPlayersFF is not treated as a valid two-player selection; only native0/1 updates the selection. Direct playing snapshots reset to their existing reference clocks and remain separate from this POWER-ON path.

`native-startup-runtime.test.ts` replays all1533 retained inputs continuously with reset(false), no native initialization helper and no mid-run correction. It compares initial fullFF RAM, generated cold RAM, every startup/title/load control, frame counter, RNG and interval, followed by World1-1 score/coins/timer/camera/Mario and the full supported enemy bank through PlayerRdy+2. All seven cases pass. The focused startup/life-screen/life-flow/GameOver/ordinary-load set passes43 tests; targeted runtime TypeScript diagnostics are0. Pixel proof remains a separate atomic consumer check; these state tests do not establish image equivalence.

Demo playback after DemoTimer0 and title-initializer reentry remain explicit `nativeStartup.unsupported` reasons. A present startup object is not permission to mark those regions verified. No new pause or other gameplay investigation is included in this unit.
