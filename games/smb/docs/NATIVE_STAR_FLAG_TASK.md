# Native castle flag task

`native-star-flag.ts` follows PlayerEndLevel and RunStarFlagObj in native byte units. PlayerEndLevel checks task5 before the actor pass, so a task4→5 transition cannot load the next area until the following dispatch. Castle entry starts task1; it selects fireworks from the timer's last digit, then task2 trades one timer unit for50 points. Task3 raises rawY144 through113 before setting that enemy slot's EnemyIntervalTimer to6. Task4 waits for that timer and EventMusicBuffer to reach0. The shared NMI divider, not an area-frame phase, controls interval expiration.

Fireworks use the ordinary enemy slot's ExplosionTimerCounter and ExplosionGfxCounter. RunFireworks decrements the byte timer, reloads8 on expiration and advances a cell. Cell3 erases the actor and awards500. InitFireworks runs in ascending enemy-slot order: a lower free slot may decrement the shared FireworksCounter before the StarFlag actor sees it. The fixture records that preceding birth as an explicit actor input.

Reproduce with `npx tsx tools/harness/native-star-flag-events.ts --traces DIR --corpus DIR --out tests/fixtures/native-star-flag-events.json`. Across32 retained and336 mood recordings (5,178,452 authenticated native samples), the fixture covers533,547 live ID49 end-walk rows and24,648 fireworks rows, with0 mismatches. This pure primitive does not yet establish runtime slot allocation, parser-created castle flag births, pending music queue ownership or continuous level transitions; those remain integration work. It introduces no level/frame-dependent constants.
